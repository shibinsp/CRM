Zusätzlich zu `dev`, `dev:build`, `dev:add` und `dev:typecheck` bietet die `yarn beeax` CLI Befehle zum Ausführen von Funktionen, Anzeigen von Logs und Verwalten von App-Installationen.

## Funktionen ausführen (`yarn beeax dev:function:exec`)

Eine Logikfunktion manuell ausführen, ohne sie über HTTP, Cron oder ein Datenbankereignis auszulösen:

```bash filename="Terminal"
# Execute by function name
yarn beeax dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn beeax dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn beeax dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the post-install function
yarn beeax dev:function:exec --postInstall
```

## Funktionsprotokolle ansehen (`yarn beeax dev:function:logs`)

Ausführungsprotokolle für die Logikfunktionen Ihrer App streamen:

```bash filename="Terminal"
# Stream all function logs
yarn beeax dev:function:logs

# Filter by function name
yarn beeax dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn beeax dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
Dies unterscheidet sich von `yarn beeax docker:logs`, das die Docker-Container-Logs anzeigt. `yarn beeax dev:function:logs` zeigt die Funktionsausführungsprotokolle Ihrer App vom BeeAX-Server.
</Note>

## Generieren des typisierten Clients (`yarn beeax dev:generate-client`)

Generieren Sie den typisierten API-Client (`beeax-client-sdk`) erneut aus dem Schema des aktiven Remotes, ohne eine App zu erstellen oder zu synchronisieren. Verwenden Sie ihn, um in jedem Projekt einen typisierten Client zu erhalten – zum Beispiel für einen Backend-Dienst in einem separaten Repository –, der mit Ihrer BeeAX-Instanz kommuniziert:

```bash filename="Terminal"
# In your project (no BeeAX app definition required)
yarn add beeax-sdk beeax-client-sdk

# Connect to the BeeAX instance to generate the client from
yarn beeax remote:add

# Generate the typed client into node_modules/beeax-client-sdk
yarn beeax dev:generate-client
```

Importieren Sie dann den Client in Ihrem Code:

```typescript
import { CoreApiClient } from 'beeax-client-sdk/core';
```

Führen Sie den Befehl erneut aus, wann immer sich Ihr Datenmodell ändert, um die generierten Typen zu aktualisieren.

<Note>
Der Client wird in `node_modules` generiert, daher wird er nicht zusammen mit Ihrem Code eingecheckt. Führen Sie `yarn beeax dev:generate-client` nach jeder Installation aus (zum Beispiel in einem `postinstall`-Skript oder in CI).
</Note>

## Eine App deinstallieren (`yarn beeax app:uninstall`)

Entfernen Sie Ihre App aus dem aktiven Arbeitsbereich:

```bash filename="Terminal"
yarn beeax app:uninstall

# Skip the confirmation prompt
yarn beeax app:uninstall --yes
```

## Remotes verwalten

Ein **Remote** ist ein BeeAX-Server, mit dem sich Ihre App verbindet. Während der Einrichtung erstellt das Scaffolding-Tool automatisch eines für Sie. Sie können jederzeit weitere Remotes hinzufügen oder zwischen ihnen wechseln.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn beeax remote:add

# Connect to a local BeeAX server (auto-detects port 2020 or 3000)
yarn beeax remote:add --local

# Add a remote non-interactively (useful for CI)
yarn beeax remote:add --url https://your-beeax-server.com --api-key $TWENTY_API_KEY --as my-remote

# List all configured remotes
yarn beeax remote:list

# Set the active remote
yarn beeax remote:use <name>
```

Ihre Anmeldedaten werden in `~/.beeax/config.json` gespeichert.
