Au-delà de `dev`, `dev:build`, `dev:add` et `dev:typecheck`, la CLI `yarn beeax` fournit des commandes pour exécuter des fonctions, consulter les journaux et gérer les installations d'applications.

## Exécuter des fonctions (`yarn beeax dev:function:exec`)

Exécutez une fonction logique manuellement sans la déclencher via HTTP, cron ou un événement de base de données :

```bash filename="Terminal"
# Execute by function name
yarn beeax dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn beeax dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn beeax dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the post-install function
yarn beeax dev:function:exec --postInstall
```

## Afficher les journaux des fonctions (`yarn beeax dev:function:logs`)

Diffuser en continu les journaux d'exécution des fonctions logiques de votre application :

```bash filename="Terminal"
# Stream all function logs
yarn beeax dev:function:logs

# Filter by function name
yarn beeax dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn beeax dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
Ceci est différent de `yarn beeax docker:logs`, qui affiche les journaux du conteneur Docker. `yarn beeax dev:function:logs` affiche les journaux d'exécution des fonctions de votre application depuis le serveur BeeAX.
</Note>

## Génération du client typé (`yarn beeax dev:generate-client`)

Régénérez le client API typé (`beeax-client-sdk`) à partir du schéma du remote actif, sans compiler ni synchroniser une application. Utilisez-le pour obtenir un client typé dans n’importe quel projet — comme un service back-end hébergé dans un dépôt distinct — qui communique avec votre instance BeeAX :

```bash filename="Terminal"
# In your project (no BeeAX app definition required)
yarn add beeax-sdk beeax-client-sdk

# Connect to the BeeAX instance to generate the client from
yarn beeax remote:add

# Generate the typed client into node_modules/beeax-client-sdk
yarn beeax dev:generate-client
```

Puis importez le client dans votre code :

```typescript
import { CoreApiClient } from 'beeax-client-sdk/core';
```

Relancez la commande chaque fois que votre modèle de données change afin d’actualiser les types générés.

<Note>
Le client est généré dans `node_modules`, il n’est donc pas versionné avec votre code. Exécutez `yarn beeax dev:generate-client` après chaque installation (par exemple dans un script `postinstall` ou dans un pipeline CI).
</Note>

## Désinstaller une application (`yarn beeax app:uninstall`)

Supprimez votre application de l'espace de travail actif :

```bash filename="Terminal"
yarn beeax app:uninstall

# Skip the confirmation prompt
yarn beeax app:uninstall --yes
```

## Gestion des remotes

Un remote est un serveur BeeAX auquel votre application se connecte. Lors de la configuration, le générateur en crée un automatiquement pour vous. Vous pouvez ajouter d’autres remotes ou basculer entre eux à tout moment.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn beeax remote:add

# Connect to a local BeeAX server (auto-detects port 2020 or 3000)
yarn beeax remote:add --local

# Add a remote non-interactively (useful for CI)
yarn beeax remote:add --url https://your-beeax-server.com --api-key $TWENTY_API_KEY --as my-remote

# List all configured remotes
yarn beeax remote:list

# Set the active remote
yarn beeax remote:use <name>
```

Vos identifiants sont stockés dans `~/.beeax/config.json`.
