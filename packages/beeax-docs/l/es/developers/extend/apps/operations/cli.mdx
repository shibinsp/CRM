Más allá de `dev`, `dev:build`, `dev:add` y `dev:typecheck`, la CLI de `yarn beeax` proporciona comandos para ejecutar funciones, ver registros y gestionar instalaciones de aplicaciones.

## Ejecutar funciones (`yarn beeax dev:function:exec`)

Ejecuta manualmente una función de lógica sin activarla mediante HTTP, cron o evento de base de datos:

```bash filename="Terminal"
# Execute by function name
yarn beeax dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn beeax dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn beeax dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the post-install function
yarn beeax dev:function:exec --postInstall
```

## Ver registros de funciones (`yarn beeax dev:function:logs`)

Transmitir en tiempo real los registros de ejecución de las funciones de lógica de tu aplicación:

```bash filename="Terminal"
# Stream all function logs
yarn beeax dev:function:logs

# Filter by function name
yarn beeax dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn beeax dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
Esto es diferente de `yarn beeax docker:logs`, que muestra los registros del contenedor de Docker. `yarn beeax dev:function:logs` muestra los registros de ejecución de funciones de tu aplicación desde el servidor de BeeAX.
</Note>

## Generando el cliente tipado (`yarn beeax dev:generate-client`)

Regenera el cliente de API tipado (`beeax-client-sdk`) a partir del esquema del remoto activo, sin compilar ni sincronizar una aplicación. Úsalo para obtener un cliente tipado en cualquier proyecto — como un servicio backend que vive en un repositorio separado — que se comunica con tu instancia de BeeAX:

```bash filename="Terminal"
# In your project (no BeeAX app definition required)
yarn add beeax-sdk beeax-client-sdk

# Connect to the BeeAX instance to generate the client from
yarn beeax remote:add

# Generate the typed client into node_modules/beeax-client-sdk
yarn beeax dev:generate-client
```

Luego importa el cliente en tu código:

```typescript
import { CoreApiClient } from 'beeax-client-sdk/core';
```

Vuelve a ejecutar el comando cada vez que cambie tu modelo de datos para actualizar los tipos generados.

<Note>
El cliente se genera dentro de `node_modules`, por lo que no se incluye en tus commits de código. Ejecuta `yarn beeax dev:generate-client` después de cada instalación (por ejemplo, en un script de `postinstall` o en CI).
</Note>

## Desinstalar una aplicación (`yarn beeax app:uninstall`)

Elimina tu aplicación del espacio de trabajo activo:

```bash filename="Terminal"
yarn beeax app:uninstall

# Skip the confirmation prompt
yarn beeax app:uninstall --yes
```

## Gestión de remotos

Un **remoto** es un servidor de BeeAX al que se conecta tu app. Durante la configuración, el generador crea uno automáticamente para ti. Puedes añadir más remotos o cambiar entre ellos en cualquier momento.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn beeax remote:add

# Connect to a local BeeAX server (auto-detects port 2020 or 3000)
yarn beeax remote:add --local

# Add a remote non-interactively (useful for CI)
yarn beeax remote:add --url https://your-beeax-server.com --api-key $TWENTY_API_KEY --as my-remote

# List all configured remotes
yarn beeax remote:list

# Set the active remote
yarn beeax remote:use <name>
```

Tus credenciales se almacenan en `~/.beeax/config.json`.
