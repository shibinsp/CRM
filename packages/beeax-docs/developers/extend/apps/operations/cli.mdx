Beyond `dev`, `dev:build`, `dev:add`, and `dev:typecheck`, the `yarn beeax` CLI provides commands for executing functions, viewing logs, and managing app installations.

## Executing functions (`yarn beeax dev:function:exec`)

Run a logic function manually without triggering it via HTTP, cron, or database event:

```bash filename="Terminal"
# Execute by function name
yarn beeax dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn beeax dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn beeax dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the post-install function
yarn beeax dev:function:exec --postInstall
```

## Viewing function logs (`yarn beeax dev:function:logs`)

Stream execution logs for your app's logic functions:

```bash filename="Terminal"
# Stream all function logs
yarn beeax dev:function:logs

# Filter by function name
yarn beeax dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn beeax dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
This is different from `yarn beeax docker:logs`, which shows the Docker container logs. `yarn beeax dev:function:logs` shows your app's function execution logs from the BeeAX server.
</Note>

## Generating the typed client (`yarn beeax dev:generate-client`)

Regenerate the typed API client (`beeax-client-sdk`) from the active remote's schema, without building or syncing an app. Use it to get a typed client in any project — like a backend service living in a separate repository — that talks to your BeeAX instance:

```bash filename="Terminal"
# In your project (no BeeAX app definition required)
yarn add beeax-sdk beeax-client-sdk

# Connect to the BeeAX instance to generate the client from
yarn beeax remote:add

# Generate the typed client into node_modules/beeax-client-sdk
yarn beeax dev:generate-client
```

Then import the client in your code:

```typescript
import { CoreApiClient } from 'beeax-client-sdk/core';
```

Re-run the command whenever your data model changes to refresh the generated types.

<Note>
The client is generated inside `node_modules`, so it is not committed with your code. Run `yarn beeax dev:generate-client` after every install (for example in a `postinstall` script or in CI).
</Note>

## Uninstalling an app (`yarn beeax app:uninstall`)

Remove your app from the active workspace:

```bash filename="Terminal"
yarn beeax app:uninstall

# Skip the confirmation prompt
yarn beeax app:uninstall --yes
```

## Managing remotes

A **remote** is a BeeAX server that your app connects to. During setup, the scaffolder creates one for you automatically. You can add more remotes or switch between them at any time.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn beeax remote:add

# Connect to a local BeeAX server (auto-detects port 2020 or 3000)
yarn beeax remote:add --local

# Add a remote non-interactively (useful for CI)
yarn beeax remote:add --url https://your-beeax-server.com --api-key $TWENTY_API_KEY --as my-remote

# List all configured remotes
yarn beeax remote:list

# Set the active remote
yarn beeax remote:use <name>
```

Your credentials are stored in `~/.beeax/config.json`.
